## 使用方法

只修改下表中的 **“调研主题”** 一列，不需要修改脚本。

- 填写具体主题：当天 Codex 会自动生成英文标题、文件名、分支名、调研报告和 Pull Request。
- 填写 `待安排`：当天跳过调研，不生成空报告，也不创建 Pull Request。
- 同一主题连续多天：Codex 会自动识别为第 1、2、3……组，每组调研 10 个项目，并尽量避免重复项目。
- 同一主题累计 5 份日报审核合并到 `main` 后，另按 `办公空间行业五次调研汇总_SOP.md` 生成一份行业汇总和独立审核 PR；未满 5 份时不触发。
- 修改只对尚未执行的日期自动生效；已经过去的日期如需补做，需要手动运行对应日期。
- 请保留表头、日期和竖线 `|`，只替换主题文字。

## 每日自动执行规则

1. 从本表读取当天“调研主题”；主题为“待安排”时结束当天任务。
2. 从远端 `main` 读取最新版 `办公空间调研全流程_SOP.md`。
3. 选取 10 个真实且可核验的项目，同主题不同日期尽量不重复项目。
4. 报告不加入逐项目案例分析和空间类型编码矩阵；软装部分只保留软装家具之间的搭配方法。
5. 自动生成安全的英文文件名和分支标识，建立独立研究分支、commit 和 Pull Request。
6. Pull Request 只供审核，禁止自动合并。
7. 尝试把项目图片导入 Eagle 的 `办公空间案例库/办公`；失败时明确记录“尚未导入”。
8. 用户明确审核通过前，不归档到 Obsidian。
9. 每次执行时检查是否有同主题 5 份已审核日报但尚无行业汇总 PR 的情况；如有，按行业汇总 SOP 补建一次。日报与汇总分别提交 PR，均禁止自动合并。

## 防重复规则

- 若当天同名报告、远端分支或 Pull Request 已存在，先核验状态，只补做缺失步骤。
- 同一主题的后续批次必须检查该主题此前报告，优先排除已使用项目。
- 所有“已上传、已导入、已归档”必须有实际证据；无法完成时明确说明原因。
